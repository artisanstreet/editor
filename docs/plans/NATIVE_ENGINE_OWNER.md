# E4 — Native Engine Process Owner (Backend)

Status: reviewed proposal against immutable `52ee041` ([PR #120](https://github.com/artisanstreet/editor/pull/120), `DirectoryController`/`ForgeListener`). This plan is not a runtime implementation or shipping approval.
Prerequisite: [native engine-first workflow](NATIVE_ENGINE_FIRST_WORKFLOW.md), published in [PR #122](https://github.com/artisanstreet/editor/pull/122). References to `frozen-e1` below mean its settled E1 contract in section 3; proposed APIs remain implementation work.

## 1. Invariant order and lifetimes (one authoritative owner)

Order (frozen-e1 §2-3, `run_launch.rs:1-15`): `queue → claim → launch_claimed_run` (DB, `provider_binding=NULL`, `run_launch.rs:702-721`) → owner spawns external process / `CreateSession` (external, non-transactional) → `bind_run_provider(BindRunProvider{claimed, receipt, start_key, credentials, expected_launch_at, bound_at, binding_version, ProviderBindingBytes 1..262144}) → Result<Bound|AlreadyBound>` (frozen-e1 §3, `run_binding.rs` proposed) — BEFORE any `Prompt`. `Bound`/`AlreadyBound`/`AlreadyStarted` are payload-free receipts (`BoundRunReceipt{run_id, thread_id, message_id, generation, binding_version, bound_at}`); none proves external delivery or authorizes resubmission. Live attempt holds private one-shot authority; replay carries historical info only. E1 checks `claimed.updated_at <= expected_launch_at <= bound_at`, `lease_expiry > bound_at`, generation = receipt.generation.
Never Prompt if `bind` returns error; unknown external outcome after `CreateSession`/`Prompt` is handled by exact idempotent replay of the same `bind`/`launch` parameters or conservative `interrupted` disposition — no blind Prompt retry.

Facade: `EngineOwner` `!Clone`, caller-supplied `tokio::runtime::Handle` (precedent `directory_controller.rs:344-386`). No self-made runtime, no global map. Owner task `run_owner` owns exactly one active engine child at a time: exact `tokio::process::Child` (retain until `wait()` reap, `tokio-1.53.1/src/process/mod.rs:1222-1396`, `kill_on_drop(true)` best-effort only), taken stdin lifeline (`process.rs:140-171`), stdout/stderr `ChildStdout/ChildStderr`, and HTTP connections. Generation burned via `GenerationAllocator` (`operation.rs:70-115`) per spawn.
Cardinality: single-active-run owner (one `Child` + its connections). Queuing is admission (`try_send` → `Busy`/`Unavailable`, `tokio-1.53.1/src/sync/mpsc/bounded.rs:924-934`) of distinct `run_id` operations, not parallel ownership. No second `Child` before observed reap; no `HashMap<run_id,Child>`.
Cancel: dedicated out-of-band `CancelHandle` (`tokio::sync::watch` + `mpsc`), not a queued job behind the operation it must stop. `control.wait()` participates in `biased select!` with fixed precedence `shutdown > cancel > deadline > completion` (`operation.rs:12-14`). Immediate cleanup: close lifeline, terminate driven `Connection`s, `start_kill()` then bounded `wait()`.
Shutdown/join: signal-before-future (`directory_controller.rs:483-534`): `shutdown()` raises `CancelHandle` then returns future retaining own `watch::Receiver::changed()` waiter (`tokio-1.53.1/src/sync/watch.rs:818-820` cancel-safe) and `JoinHandle` across `Pending`. Verdict cached once (`observed_join: Option<bool>`) because polled-after-completion `JoinHandle` panics (`runtime/task/harness.rs`). `shutdown().await` may return `Joined | TaskLost | Quarantined` — `Quarantined` does not prove reaped/idle; eventual reap parks forever retaining custody (`operation.rs:199-220`).
Distinctions: process `wait()` exit ≠ SSE EOF ≠ editor disconnect ≠ validated provider terminal. `ExitStatus success` alone is never terminal.

## 2. Reuse decision

Reuse custody shape, not protocol bytes. `operation.rs`/`process.rs` are specialized to 18-byte ASDR codec; do not copy. No generic framework.
Proposed `modules/backend/src/engine_owner/` (engine-specific composition):
`mod.rs` — `EngineOwner`, `EngineOwnerConfig{engine_executable: PathBuf}`, `EngineLimits{readiness, health, prompt, sse, close: Duration}` (durations validated via `Instant::now().checked_add` `listener.rs:95-114`), `EngineBounds{max_json_body: usize, max_sse_line: usize, max_sse_event: usize, max_readiness_line: usize, max_headers: usize, max_buf_bytes: usize, stderr_cap_bytes: usize, sink_capacity: usize, control_capacity: usize}` (integer counts/capacities validated `>0` and against hyper minima, separate from duration `checked_add`), no defaults. Choose `max_buf_size` (`hyper-1.11.0/src/client/conn/http1.rs:520-528`, panics if `<8192` library validation not shipping default) not conflicting `read_buf_exact_size` (`:500-509`).
`operation.rs` — `GenerationAllocator`, `Job{run_id, kind: Prompt|Interrupt, deadline, control}`, `run_owner`, `quarantine_tail`.
`process.rs` — `LaunchRecipe::Production{executable}` (+ `Fixture` `cfg(test)` only, precedent `process.rs:54-70`), `spawn_engine` (`piped`/`kill_on_drop`/`CREATE_NO_WINDOW`, `tokio-1.53.1/src/process/mod.rs:638-667`), `LifelineWriter`, `StderrCounter` (count-only, cap counted not retained).
`readiness.rs` — byte-bounded readiness line parser.
`http.rs` — hyper connection ownership (see §4).
`framing.rs` — SSE line/event framer (byte-bounded).
`observation.rs` — bounded normalizer → proposed admission type.
Unchanged: `directory_controller.rs` + `directory_controller/*`, `listener.rs` (caller-owned lifetimes, lease-based shutdown), `app.rs:20-58` (E6 gate: verified OS custody BEFORE `ForgeStorage::open`+migrate remains blocked).

## 3. Legacy contract (behavioral evidence, not shipping policy)

Readiness (`service.ts:16-165`): stdout single strict JSON line `{"url": NonEmptyString}` terminated by `\n` (`\r` trimmed), legacy `64KiB`/`15s` evidence not native defaults, secret `randomBytes(32).base64url` in `OPENCODE_PASSWORD`/`OPENCODE_SERVER_PASSWORD=""` with `...process.env` spread, endpoint `http:` loopback `127.0.0.1`/`::1` port `1..65535` no credentials, then `GET /api/health` (`protocol.ts:270-272`) authenticated with `Basic base64(opencode:password)` (`protocol.ts:206`) and version pin, `10s` health timeout, `3s` close. Do not inherit ambient env/auth silently; native assembly selects explicit env + `Authorization`.
Sessions (`protocol.ts:248-355`): `POST /api/session` `{agent, location{directory}, model{id,providerID,variant}}` → `id`; `POST /api/session/:id/prompt` `{delivery, files{uri,name}, id, resume, text}`; `POST /api/session/:id/interrupt`; `GET /api/session/:id/message?limit=&order=`; `POST /api/session/:id/wait`; `GET /api/event` (global SSE), `GET /api/experimental/session/:id/log?after=&follow=` (durable log SSE). Native uses `hyper` for HTTP; SSE is byte `event:`/`data:` lines per `protocol.ts:150-200` (`pending: string` not bounded proof).
Terminal vs sync: `normalizer.ts:294` `log.synced` returns `[]` — it is ONLY a replay cursor/sync marker, never terminal. Terminal validated only as `session.execution.succeeded` → `completed`, `failed` → `failed`, `interrupted` with `data.reason==="user"` → `cancelled` else `interrupted` (`normalizer.ts:325-334`). Preserve that typed distinction; do not collapse every `interrupted` to `cancelled`. EOF on SSE, `Child` exit `0`, or `shutdown` result are distinct from `run_terminal` observation.
Sensitive handling: raw SSE frames may carry prompt/tool content + secrets; never persist raw frames nor `Authorization` in durable errors/telemetry.

## 4. HTTP/SSE custody (one concrete hyper direction)

Locked graph `hyper 1.11.0` `hyper-util 0.1.20` `http-body-util 0.1.5` `http 1.5.0` `bytes 1.12.1` present via `Cargo.Bazel.lock` but no direct `artisan-backend` dep (`backend/Cargo.toml:8-19`) — promotion is root-owned prerequisite.
Pinned API (read): `hyper::client::conn::http1::handshake(io)` → `(SendRequest<B>, Connection<T,B>)` (`hyper-1.11.0/src/client/conn/http1.rs:140-148`), `Builder::handshake` (`:536-590`) with `max_headers` = maximum header COUNT (`:469-485`) / `max_buf_size` = maximum HTTP read-buffer BYTES (`:511-529`, library panics if `<8192` validation not shipping default) — distinct from `read_buf_exact_size` (`:500-509`, do not set both), `SendRequest::send_request/try_send_request` (`:213-266`, dropping future closes that HTTP1 connection `:`206-212, no capacity/reserve API — only `poll_ready`/`ready`/`is_closed`), `Connection: Future<Output=hyper::Result<()>>` must be polled (`:301-308`), `#[must_use]` drop closes IO (`:60-67`); `hyper-util::rt::tokio::TokioIo<T>` adapters (`hyper-util-0.1.20/src/rt/tokio.rs:127-276`); `http-body-util::Limited::new(inner, limit)` bounds accepted DATA `Frame`s only (`http-body-util-0.1.5/src/limited.rs:40-65`, header/transport not bounded); `tokio::task::JoinHandle` drop detaches not cancels (`tokio-1.53.1/src/runtime/task/join.rs:18-35,324-352`), `abort()` explicit (`:183-228`).
Chosen: manual `hyper::client::conn::http1` with `TokioIo<tokio::net::TcpStream>`.
+ Connect target: validated ready URL's actual loopback address + validated nonzero port via `tokio::net::TcpStream::connect(addr)` (never `127.0.0.1:0` — that is Forge listen bind). Validate loopback before connect.
+ Stream set selected from legacy `engine.ts:707-743`: global `GET /api/event` (readiness `server.connected`, `permission.asked`, `form.created`, durable fallthrough) PLUS per-session `GET /api/experimental/session/:id/log?after=&follow=true` (durable log) — each live SSE response has its OWN independently driven owned `handshake`→`(SendRequest, Connection)` and `JoinHandle<hyper::Result<()>>`, plus a separate control `handshake`→`(SendRequest, Connection)` for short RPCs. Never multiplex two live `IncomingBody` on one HTTP/1 `Connection` (dropping one `send_request` future closes the whole connection `http1.rs:206-212`).
+ Each live SSE response has a `Connection` future driven on the supplied handle. Handshake produces `(tx, conn)`; owner spawns `conn` yielding `JoinHandle<hyper::Result<()>>` (`http1.rs:301-308`, `join.rs:18-35`) and retains that exact handle plus a `watch` stop signal; each settled result is cached once: `Ok(Ok(()))` success, `Ok(Err(hyper::Error))` connection error, or `Err(join_error)` classified with `is_cancelled()` / `is_panic()`. Follow/replay handoff is explicit: end the old body, then settle its retained driver using section 5's abort/await/cached-result custody before a new `handshake`+request with `after=cursor` (cursor from `latest_sequence`, `engine.ts:262-278`). Do not drop an unjoined handle or claim ownership of the already-moved `Connection`; unresolved settlement follows the same quarantine rule. No implicit reuse.
+ Control: separate `control` `handshake`→`(SendRequest, Connection)` for short RPCs (`health/prompt/interrupt/wait/message.list`) driven as its own `JoinHandle<hyper::Result<()>>`. `control_capacity` bounds the owner's own bounded `mpsc::channel<Job>` admission queue (`control_capacity>0` checked), NOT Hyper `SendRequest` — Hyper has no capacity/reserve API, only `poll_ready`/`ready`/`send_request`/`try_send_request`/`is_closed` (`http1.rs:152-266`); `prompt` reserves one queue slot via `try_send`, `interrupt`/`cancel` is out-of-band and never queues behind prompt — it aborts the in-flight `send_request` future (which closes that control `Connection` per `http1.rs:206-212`) and sends on a fresh or already-idle control `Connection`. No automatic Prompt retry after cancellation/close (`is_closed` true → `try_send_request` `canceled` error, not retried).
+ Verification still required: `backend/Cargo.toml` add `hyper {features=["client","http1"]}`, `hyper-util {features=["tokio"]}`, `http-body-util`, `http`, `bytes`, `base64`; `BUILD.bazel` crate mapping; `tokio` features `net,io-util,sync,time`.

## 5. Bounded parsing, UTF-8, normalization, admission

Readiness: count raw `stdout` bytes before `String`, newline search on bytes, fail `MalformedFrame`/`OversizedOutput` if `> max_readiness_line` before `serde_json::from_slice`. Value is caller-supplied `EngineBounds.max_readiness_line`.
HTTP JSON: use `Content-Length` pre-check + `Limited::new(body, max_json_body)` then `BodyExt::collect().await` (`http-body-util-0.1.5/src/lib.rs:101-111`) — bounds accepted DATA frames (`limited.rs:40-65`), not total allocation. Bound SSE aggregation separately: SSE layer counts `pending_line_bytes` and `current_event_bytes` on byte slices before `String`/`serde_json`; overflow → typed bounded rejection before allocation.
Transport bounds: caller-supplied `max_headers: usize` → `Builder::max_headers` (header COUNT, `:469-485`), caller-supplied `max_buf_bytes: usize` → `Builder::max_buf_size` (read-buffer BYTES, `:511-529`, library minimum `8192` is validation not default; choose `max_buf_size` not conflicting `read_buf_exact_size` `:500-509`). These bound hyper parser/read buffers; `Limited::new` (`limited.rs:40-65`) bounds only accepted DATA frames, not total memory.
UTF-8: streaming `Bytes` chunks kept as `Vec<u8>` remainder; `std::str::from_utf8` on complete lines, incomplete sequences stay as bytes — lossless.
Assistant content: never truncate. If delta exceeds `4096`, emit lossless consecutive chunks each `<=4096` sharing stable `chunk_id = format!("{}:{}:{}", native_id, durable_seq, chunk_index)` and monotonic `sequence = durable_seq` (no `0` invention). Alternative typed rejection `OversizedContent{phase}` with no false `completed`. Bounded `file`/`patch` admission through verified `4096` limit remains.
Bounded catalog diagnostics only may be lossy by explicit policy (`truncate{suffix:"…[truncated]"}`) and are never substituted for assistant content.
Proposed interface (new, not `command_admission.rs` reducer): `enum EngineObservation{ TextDelta{run_id, seq, chunk_id, delta}, TextCompleted{..}, Reasoning{..}, ToolStatus{..}, FileChange{..}, Terminal{state: Completed|Failed|Cancelled|Interrupted, reason?:String, error_ref?}, Diagnostic{level, message: bounded}}` — no `raw_frame`, no secret envelope, no invented default sequence. `EngineOwner` proposes via bounded sink; E2 co-commits `turn lifecycle + revision + patches` transactionally (not yet implemented at `52ee041` — no competing transaction claimed).
Connection driver custody: after `tokio::spawn(conn)` yielding `JoinHandle<hyper::Result<()>>` (`http1.rs:301-308`, `join.rs:18-35`), owner retains that exact handle in its state + `watch::Sender<bool>` stop. On `cancel/shutdown/deadline`: signal stop, `handle.abort()` (`join.rs:183-228`), then `await handle` exactly once capturing nested `Ok(Ok(()))` (clean shutdown), `Ok(Err(hyper::Error))` (connection error), `Err(JoinError)` cancelled (`is_cancelled()`) or panic/other (`is_panic()`) (`join.rs:324-352`); each settled result cached once. While a `JoinHandle` is still pending, owner remains responsible — keeps `Child` + pipes retained, permit not released, deadlines/cancel still serviced via `biased select!`; no `async Drop`. Unresolved join (abort/timeout did not settle) or unobserved child reap → irreversible `Quarantined` retaining resources and permit, never reported as `idle`/`reaped`. Child `wait()` reap and driver `join()` are distinct; both must settle to release.
Sink backpressure (wakeable): `try_send`-only parking is not wakeable. Retain the pending `EngineObservation` plus ONE owned `Sender::reserve_owned()` future (`tokio-1.53.1/src/sync/mpsc/bounded.rs:1188-1285`) across `Pending` — `reserve_owned` takes owned `Sender` (`sender.clone().reserve_owned().await` → `Result<OwnedPermit<T>, SendError<()>>`), so retain `sender.clone()` and the future. On success bind `OwnedPermit` and `permit.send(observation)` exactly once; `Err(SendError(()))` (closed sink) is a typed failure propagated, not `_`-ignored. `tokio::select!{biased; shutdown/cancel/deadline, res = &mut reserve_fut => match res {Ok(p)=>p.send(obs), Err(e)=> typed failure} }` preserves wake registration. Dropping/recreating waiter each poll loses registration and payload — state lives in owner across losing select branches; no lost observation. Bounded Job admission (`try_send` on `Job` queue, `control_capacity`) is separate from bounded observation delivery (`sink_capacity`).
